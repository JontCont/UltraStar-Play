# 開發計畫

本計畫以 [規格範圍](README.md) 為準；進度與相依性只記錄在 [任務清單](tasks.md)，不在多份文件維護狀態副本。

## P0：匯入與建立可重現基線

1. 確認要使用的上游版本，記錄 tag、完整 commit、來源及授權。
2. 確認匯入目錄與版本管理安排，保留現有規劃與 AI 指引。
3. 依該 checkout 的要求準備 Unity、建置工具及必要依賴，不預設下載 AI 模型。
4. 先跑原版，建立 Windows player、相關測試及人工操作基線。
5. 用實際程式碼修正架構研究文件，建立後續修改所需的架構知識。

2026-10-24 補充決策：使用者核准主遊戲直接採用已安裝的 Unity `6000.6.7f1`，略過建立 6.5 執行基線。先完成引擎相容性驗證，與 UI 翻新分開；不能把後續錯誤直接認定為升級造成。

同日另核准 Companion 升級至相同 Editor 並遷移 URP，由 T03C 獨立追蹤，不受桌機核心測試 T04 阻擋。這是既有手機程式的引擎維護，不代表已核准新手機功能或視覺改版；Android／iOS 模組、手機實機與配對仍需後續驗證。

出口條件：原版可重現執行；若原版失敗，先記錄並判斷是否阻擋後續工作，不把上游既有問題當成翻新結果。

## P1：現況盤點與設計確認

- 盤點主畫面、選歌、演唱、結算與設定流程。
- 盤點共用控制項、主題、焦點導覽、輸入方式及在地化。
- 確認首版頁面、視覺草案、螢幕尺寸、手機需求與驗收硬體。
- 分離純視覺調整與行為變更；後者須個別確認。

出口條件：使用者核准首版範圍與視覺方向，且每個頁面有明確驗收項目。未核准前不大規模改 UI。

## P2：共用 UI 與瀏覽流程

- 先更新相關架構 skill，再調整需要的共用樣式與控制項。
- 以主畫面及選歌頁驗證設計方向，採小批次交付。
- 共用 UI 若被 Companion 使用，必須檢查其相容性。
- 沿用既有資料來源、掃描與選歌邏輯，避免混入歌庫重寫。

出口條件：主要瀏覽與選歌流程符合核准方案，並通過針對性驗證。

## P3：演唱、結算與設定

- 調整歌詞、音符、玩家資訊與分數的呈現，不變更核心判定。
- 更新結算與必要設定頁，保留麥克風校正與錯誤處理。
- 驗證歌曲編輯器仍可工作；未核准時不擴大為編輯器重寫。
- 若首版確認需要手機，再另行驗證 Companion 連線；未確認則跳過新增整合工作。

出口條件：封裝 player 可完成選歌到結算，既有資料、校正與輸入行為未被破壞。

## P4：回歸與交付

- 執行受影響的 EditMode／PlayMode 測試及 Windows player 人工回歸。
- 測試本機離線使用、重新啟動、無麥克風、無效歌曲與播放失敗等情境。
- 依基線比較啟動、掃歌、畫面更新及資源使用；門檻由 P0 實測後訂定，不憑空宣稱效能提升。
- 驗證封裝、授權與第三方資產，提供可重現啟動方式及已知限制。
- 同步規格、任務與架構 skills。

出口條件：實際交付的 Windows 成品通過核准驗收；編輯器可執行或單純編譯成功不能取代成品驗證。

## 全程執行方式

- 每個開發任務先讀開發及架構 skills；架構異動先記錄、再修改、最後核對。
- 用實際 checkout 決定命令與路徑，不照抄可能過期的 Wiki。
- 以最小相關測試開始，只有跨層變動或針對性結果顯示需要時才擴大驗證。
- 不將尚未完成的程式、提議中的架構或未測試平台記成已支援。
